# Кубики удачи — подарок Бусеньке

Готовый проект для загрузки в GitHub и запуска Telegram Mini App. Включает последний согласованный дизайн: бордовые стеклянные кубики, мягкое полукольцо, жемчужные надписи и плавное растворение в точках. Шрифты входят в проект. Тестовые кнопки и возможность сбросить реальные подарки из интерфейса удалены.

## Что делает приложение

- Один личный получатель, заданный через `ALLOWED_TELEGRAM_ID`.
- Один подарок в календарный день по Москве; часовой пояс можно изменить.
- Одна серия из **15 открытий**, строго **20 000 ₽ суммарно**: 14 денежных подарков и одна «Фигушка» — 0 ₽.
- Денежные номиналы: 300, 500, 1 000, 1 500, 2 000 и 5 000 ₽. Возможные номиналы не обязаны встретиться все в одной серии.
- Сервер один раз формирует случайную последовательность, сохраняет её в SQLite и выдаёт очередной результат при выборе любого кубика. Повторное открытие страницы последовательность не меняет. Разные кубики не скрывают разные суммы на один день.
- Пропуск дня не сжигает подарок: 15 открытий могут занять больше 15 календарных дней.
- После 15-го открытия серия завершается. Новая серия автоматически не создаётся.
- Повторные и одновременные запросы не создают дополнительные подарки. При потере ответа повторяется тот же запрос.
- Бот присылает результат и ежедневное напоминание в 10:00 по Москве, если сегодняшний подарок ещё не открыт. Напоминания не требуют открытого Mini App.
- `/stop` выключает уведомления, `/start` включает снова. После окончания серии напоминания прекращаются.
- Дополнительно можно задать `ADMIN_CHAT_ID`, чтобы получать копии результатов в свой личный чат с ботом.

Приложение **фиксирует сумму подарка, но не переводит деньги**. Банковские переводы не подключены.

## Архитектура

Код хранится на GitHub. Один постоянно работающий сервер Node.js 24 обслуживает Mini App, проверяет Telegram `initData`, сохраняет результаты в SQLite и запускает бота через long polling. Серверу нужен постоянный диск и публичный HTTPS-адрес. Все API и интерфейс размещаются на одном домене.

**GitHub Pages для этого проекта не подходит:** он не запускает серверную часть. Обычного размещения одного HTML-файла недостаточно.

## Быстрый запуск: GitHub → Render → Telegram

### 1. Создай бота

В Telegram открой официального `@BotFather`, отправь `/newbot` и получи токен. Если бот уже есть, используй его, но останови старую программу, которая получает его обновления: этот проект должен быть единственным long-polling процессом для данного токена.

Токен не присылай в чат и не загружай в GitHub. Он хранится только в секретных переменных хостинга. `.env.example` можно публиковать: в нём нет настоящих секретов.

### 2. Загрузи проект в GitHub

Распакуй архив. Создай репозиторий и загрузи **содержимое** папки `dice-telegram-ready`, включая `public`, `src`, `scripts`, `tests`, `.github`, `package.json`, `package-lock.json`, `render.yaml`, `.gitignore` и остальные файлы.

В корне репозитория должны лежать `package.json` и `render.yaml`, а не ещё одна внешняя папка. После загрузки во вкладке Actions должен пройти workflow `Tests`.

Не загружай собственный `.env`, базу `data/`, резервные копии `backups/` и токен. Файлы с реальными данными отсутствуют в поставке.

### 3. Запусти сервер на Render

Вариант А: **New → Blueprint**, подключи репозиторий и используй `render.yaml`. Он описывает платный постоянно работающий Web Service и постоянный диск 1 GB. Проверь стоимость в Render перед созданием: платные ресурсы здесь не создавались.

Вариант Б: создай **Web Service** вручную и укажи:

| Параметр | Значение |
| --- | --- |
| Runtime | Node |
| Node version | 24 |
| Build command | `npm ci && npm test` |
| Start command | `npm start` |
| Health check | `/health` |
| Instances | 1 |
| Persistent disk | путь `/var/data`, минимум 1 GB |
| DATABASE_PATH | `/var/data/gifts.sqlite` |

В разделе Environment добавь:

| Переменная | Что указать |
| --- | --- |
| `BOT_TOKEN` | Токен из BotFather, как секрет |
| `APP_URL` | Реальный публичный HTTPS-адрес сервиса, например `https://ваше-имя.onrender.com`, без пути и завершающего слеша |
| `ALLOWED_TELEGRAM_ID` | Числовой Telegram ID Бусеньки |
| `NODE_ENV` | `production` |
| `DATABASE_PATH` | `/var/data/gifts.sqlite` |
| `TIMEZONE` | `Europe/Moscow` |
| `REMINDER_HOUR` | `10` |
| `REMINDER_MINUTE` | `0` |
| `ADMIN_CHAT_ID` | Необязательно: твой ID личного чата с ботом |

Адрес `APP_URL` должен совпадать с доменом, с которого открывается Mini App. При добавлении собственного домена обнови переменную и настройки бота.

**Если ID Бусеньки пока неизвестен:** при ручной настройке можно временно не задавать `ALLOWED_TELEGRAM_ID`. Сервер запустит бота, но доступ к подаркам будет закрыт. Пусть Бусенька отправит ему `/id`: он ответит её собственным ID. Вставь этот ID в переменную и перезапусти сервис. Через Blueprint значение можно указать после получения ID от уже запущенного бота либо первоначально разворачивать сервис вручную без этой переменной. Не назначай получателем себя для проверки реальной серии — для проверки есть отдельное демо.

Сервер должен оставаться включённым. Бесплатный спящий сервер и временная файловая система не обеспечивают сохранность SQLite и своевременные напоминания. Не запускай несколько экземпляров и не меняй получателя после начала серии.

### 4. Настрой Telegram

Открой Shell своего сервиса и выполни один раз:

```bash
npm run bot:setup
```

Скрипт проверит токен, удалит старый webhook без удаления накопленных обновлений, установит команды и кнопку «Кубики удачи» в меню бота. Затем перезапусти сервис. Если оболочка хостинга недоступна, скрипт можно выполнить на своём компьютере с Node.js 24 и теми же переменными в локальном `.env`.

В `@BotFather` выбери своего бота через `/mybots`, открой настройки **Main Mini App / Configure Mini App** и укажи `APP_URL`. Название и иконку приложения можно установить там же. Если доступна отдельная настройка Menu Button, укажи тот же адрес. Названия пунктов могут отличаться между версиями интерфейса BotFather.

После включения Main Mini App приложение открывается через кнопку профиля бота и ссылку вида `https://t.me/ИМЯ_БОТА?startapp`.

Бусенька должна открыть **личный чат с ботом и нажать «Запустить» / отправить `/start`**. Это зарегистрирует чат для уведомлений. Просто открыть URL в обычном браузере недостаточно: реальное приложение проверяет подписанные данные запуска Telegram.

Если указал `ADMIN_CHAT_ID`, сначала сам отправь `/start` этому боту. Для администратора доступ к подаркам всё равно останется закрытым, если он не получатель; это не мешает получать настроенные копии результатов.

### 5. Контроль перед передачей

1. Открой `https://твой-домен/health`: ожидается `ok: true`, `configured: true`, а после подключения к Telegram — `telegram: "running"`.
2. Чужой аккаунт не должен получать подарки; обычный браузер должен предложить открыть приложение из Telegram.
3. Пусть Бусенька отправит `/start` и откроет Mini App из бота.
4. **Первое настоящее нажатие расходует первый подарок.** Дождись результата и уведомления, закрой и снова открой приложение: результат должен сохраниться, повторный выбор сегодня закрыт.
5. На следующий календарный день по Москве появится новый выбор. Время в телефоне не определяет день выдачи.
6. На настоящем iPhone проверь скорость вращения, распад на точки и открытие окна «Варианты выигрыша». Автотесты не заменяют проверку Safari / Telegram WebView на устройстве.

## Локальная проверка без токена

Установи Node.js 24. В папке проекта:

```bash
npm ci
npm test
npm run demo
```

Открой `http://127.0.0.1:3000`. В заголовке будет пометка «демо». Этот режим использует отдельную базу `data/demo.sqlite`, не отправляет Telegram-сообщения и слушает только localhost. Реальные данные он не затрагивает. В демо также работает правило одного открытия в день; для повторного чистого теста останови демо и удали **только** `data/demo.sqlite` и его файлы `-wal` / `-shm`, если они остались. Никогда не удаляй `gifts.sqlite` ради теста.

Для производственного локального запуска скопируй `.env.example` в `.env`, заполни реальные значения и выполни `npm start`. Для Telegram всё равно понадобится публичный HTTPS-адрес; localhost как адрес Mini App не подходит.

## Docker / свой сервер

В архиве есть `Dockerfile` и `compose.yaml`. После заполнения `.env`:

```bash
docker compose up -d --build
docker compose exec gifts npm run bot:setup
```

Данные сохраняются в именованном томе `gifts-data`. Порт доступен на `127.0.0.1:3000`; направь на него свой HTTPS reverse proxy, например Caddy или Nginx. Не запускай `docker compose down -v`: эта команда удаляет том с подарками. На один токен — один активный экземпляр приложения.

## Сохранность и уведомления

- Сохраняются последовательность, открытия, сумма, подписка на уведомления, очередь сообщений и смещение Telegram updates.
- Результат и запись о необходимости отправить уведомление сохраняются в одной транзакции. Сбой отправки не откатывает подарок.
- Сетевые ошибки и Telegram 429 повторяются с паузой. Блокировка бота отключает сообщения до следующего `/start`.
- Просроченные напоминания не рассылаются за пропущенные дни; напоминание за сегодня не отправляется, если подарок уже открыт.
- Для исходящих сообщений используется очередь с повторными попытками. Если Telegram принял сообщение, а соединение оборвалось до подтверждения, при повторе возможен дубль **уведомления**; дублирования подарка и суммы не будет.
- Точная минута доставки зависит от доступности сервера и Telegram. Само напоминание планируется по серверному часовому поясу.
- Копии результатов администратору включаются только переменной `ADMIN_CHAT_ID`; чтобы их не было, оставь её пустой.

Для согласованной резервной копии SQLite на сервере:

```bash
npm run backup
```

Команда создаёт копию в `backups/`. Скачай её в отдельное безопасное место: копия на том же сервере сама по себе не защищает от потери сервера. Не публикуй копии в GitHub. Перед восстановлением останови приложение; восстанавливай базу в настроенный `DATABASE_PATH` и не оставляй старые WAL/SHM файлы рядом с восстановленной копией.

## Файлы проекта

- `public/` — интерфейс, анимация, шрифты и иконка.
- `src/game.js` — алгоритм точного бюджета.
- `src/auth.js` — проверка подписи и срока действия Telegram initData.
- `src/store.js` — SQLite, защита от повторной выдачи, очередь уведомлений.
- `src/telegram.js` — команды бота, напоминания, повторная отправка.
- `src/server.js` — HTTP API и раздача интерфейса.
- `tests/` — тесты алгоритма, авторизации, сохранения, параллельных запросов и уведомлений без обращения к реальному Telegram.
